# Full-vacuum CA bridge (LIPAc training IOC)

**Scope:** Python *training* vacuum model for VAC01, VAC02, GV, H₂/D₂ source-gas
safety valves and MFCs, and LEBT Kr MFC. Does **not** reproduce real PLC/PPS
safety logic or validate physical pump performance. Never connect to production.

## Model ownership and exceptions

- Edge inputs: PP/TP on/off; PV/SV/AIV open/close on VAC01+VAC02; NIV open/close
  on VAC01 only; GV open/close; source-gas H₂ and D₂ safety-valve open/close.
- Level inputs: `SRC:MFCH:OpenCmd`, `SRC:MFCD:OpenCmd`, `LEBT:MFC:OpenCmd`;
  their respective `Debit` setpoints in sccm.
- External read-only dependencies: `PPS:GV:OpenPermStat`,
  `PPS:SVL:{H2,D2}PermStat`, `LEBT:VAC{01,02}:LTVOpenStat` and
  `LEBT:VAC:SVForcing`. Imported into SimulationPVState. They are **never**
  written to the IOC by this bridge.
- Python outputs: only PVs emitted by the physical vacuum, valve and MFC
  models and whose name matches the strict built-in physical-output allowlist.
  Dynamic discovery is intersected with runtime ownership and the actual IOC
  records, each validated before any writes. Both vacuum stations, GV and gas
  valves are covered by this one engine clock.
- `LEBT:VAC0{1,2}:{PV,SV}OpenPrecond` are already generated by `calc` records
  in `plcInjector_StatusForOpi.db`. Python computes the compatibility formula,
  but the bridge **never writes** those PVs. Do not confuse display formulas
  with PLC valve authorizations.
- VAC02 has **no physical NIV**. Original NIV02 PVs are excluded, not simulated.
- LTV does not yet have a validated actuator model. Read its external status,
  but never fabricate an `OpenStat` readback from Python.
- `PPS:*` are external scenario states, NOT output PLC interlock emulations.

## Before deployment

Current isolated network on Debian host: Podman network `internal`, IOC
`10.0.3.16:5064`. The host already reaches `10.0.3.16`; no published TCP/UDP
ports are required for the second container. This implementation deliberately
only accepts a literal destination on `10.0.3.0/24`.

The bridge uses the repository's `config/pv_runtime_overrides.yaml` allowlist
for writes **into** the Python model and checks the Python generator ownership
for every output. IOC output schemas are allowed only if `RTYP` is `bi`/`ai`,
`DTYP` is `Injector Soft Channel`/`Soft Channel`, `SCAN` is `Passive`, `I/O Intr`,
`1 second` or `2 second`, and `INP` is constant/empty. Validation cannot prove
there is no other IOC writer. Any competing changes found after publication
cause an immediate stop. **Do not switch SCAN globally**; identify registers
that are also calculated by IOC, especially MFC readbacks with `2 second` scan.

## Install and test

From repo root, extract the provided ZIP. It adds a *new* module
`vacuum_full_bridge.py` and leaves `ca_bridge.py` (validated PP pilot) intact.

```bash
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -p test_vacuum_full_bridge.py -v
sudo podman build \
  --build-arg HTTP_PROXY=http://cproxy.iferc.local:8080 \
  --build-arg HTTPS_PROXY=http://cproxy.iferc.local:8080 \
  -f deploy/Containerfile.bridge \
  -t localhost/injector-ca-bridge:vacuum-full .
```

Stop the prior pilot to prevent simultaneous engine instances:

```bash
sudo systemctl stop injector_bridge.service
./scripts/vacuum_full_preflight.sh  # validates all output record schemas, NO writes
./scripts/vacuum_full_observe.sh    # short 10 s read-only integration
```

**Do not enable publishing if preflight fails.** Read its exact failing PV and
review that EPICS record before proceeding. An output with an `INP` link, a
non-soft DTYP or an `RTYP=calc` indicates contested ownership; resolve the
record source first, instead of bypassing the check.

Once record ownership has been reviewed and preflight succeeded, an attended,
**temporary** publish experiment (no persistent enablement):

```bash
sudo podman run --rm --name injector-vacuum-full-test \
  --network internal --read-only --security-opt no-new-privileges \
  -e EPICS_CA_AUTO_ADDR_LIST=NO -e EPICS_CA_ADDR_LIST=10.0.3.16 \
  -e BRIDGE_ALLOW_WRITES=YES -e BRIDGE_ISOLATED_ACK=YES \
  -e BRIDGE_SCOPE_ACK=FULL_VACUUM \
  localhost/injector-ca-bridge:vacuum-full \
  python -m injector_otp.epics.vacuum_full_bridge \
    --mode publish --ioc 10.0.3.16 --steps 6000 --report-every 50 \
    --max-writes-per-cycle 12 --publish-period 0.5
```

During the test, monitor in a second terminal:

```bash
export EPICS_CA_AUTO_ADDR_LIST=NO EPICS_CA_ADDR_LIST=10.0.3.16
camonitor -n LEBT:VAC01:PPOnStat LEBT:VAC02:PPOnStat \
  LEBT:GV:OpenStat LEBT:VAC01:VacSGVC LEBT:VAC02:VacSGVC
```

The readback test should start with non-gas actions (PP01/PP02 on/off) before
opening gas valves or MFCs. Simulated gas flows and pressure curves are not
calibrated. Keep full publishing explicitly attended, NEVER on auto-start.

After testing, Ctrl+C the temporary container; restart only the regular,
**read-only** service via `sudo systemctl start injector_bridge.service`.

## Permanent *observe* service (after validation)

The file `deploy/quadlet/injector_bridge_full.container` is a candidate
replacement for the existing `injector_bridge.container` (same unit and
container name, not a third concurrent service). Back up the original and
replace it only when the full bridge's observe mode is proven. It boots in
**observe** mode and requires explicit runtime flags for write tests. Use
`sudo systemctl daemon-reload` then `sudo systemctl restart injector_bridge.service`.
Do not run `systemctl enable` on generated Quadlet services.

## Constraints and known work

- Python physics is still a **reduced-order**, unvalidated six-node network.
  TP throughput to backing line F is incomplete and should be corrected before
  physically validating foreline pressure, PP-load or pumpdown transients.
- The original Pirani/Penning sensors use idealized total pressure; gas
  sensitivity/range calibration remains pending.
- The IOC currently has `.01 second` scan overruns in `injectorHV_Spark.db`.
  Do not solve these by modifying unrelated PV scans without tracing sources.
- No EPICS client can prove unique ownership only from read/write metadata.
  Audit direct links and all other clients before treating published data as
  authoritative.
- On bridge death, the last IOC readbacks may remain visible. Operational
  deployment requires an explicit bridge-health/freshness mechanism. Avoid
  unattended use of stale PVs.
- Simulated PPS and OPI preconditions do not authorize hardware action.
