# Simulation configuration

The simulation uses three different concepts that must remain separate.

## 1. PV registry

`config/pv_registry_v1_2.json` answers: **Which EPICS PVs exist?**

It is the machine-readable interface definition.

## 2. Operating parameters

`config/injector_operating_parameters.yaml` answers: **Which physical/operating values are useful as modelling references?**

It is not a startup-state database.

## 3. Simulation configuration

`config/simulation/default.yaml` answers: **In which initial external condition should this simulation instance start?**

It contains initial conditions required by the simulation but not yet generated by a physical model.

### Calculated values do not belong here

Do not configure calculated interlock outputs such as `HV_ENABLE`.

Instead, configuration supplies the input conditions and interlock logic calculates the authorization from those inputs.

## Separation of sources of truth

```
PV registry       -> interface
operating params  -> modelling reference
simulation config -> initial conditions
```

The simulation engine remains the component that calculates dynamic state and derived outputs.
