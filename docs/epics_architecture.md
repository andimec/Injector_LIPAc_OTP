# EPICS / Phoebus integration architecture

## Purpose

The simulation engine owns the simulated process state. The Soft IOC owns the EPICS representation of that state. Phoebus only interacts with EPICS PVs.

## Runtime architecture

```
Phoebus OPI
    | EPICS CA/PVA
    v
Simulation Soft IOC
    | PV bridge
    v
Simulation Engine
    |-- Control / Interlocks
    |-- Fault Manager
    |-- Physical / reduced-order models
    `-- Calculated state
```

## PV ownership

Operator inputs are written by Phoebus and consumed by the simulation: commands, setpoints and selections.

Simulation outputs are generated by the engine: readbacks, calculated values, status values and authorization results.

Initial-condition inputs are external conditions that are not yet physically modelled. Their initial values may come from simulation configuration.

## Simulation cycle

1. Soft IOC receives operator writes.
2. Engine reads command and setpoint PVs.
3. Interlock/control logic evaluates authorization.
4. Fault manager applies synthetic faults.
5. Physical/reduced-order models update.
6. Calculated states and readbacks are produced.
7. Engine publishes values through the PV bridge.
8. Soft IOC updates its EPICS records.
9. Phoebus receives EPICS monitor updates.

The physical model must not call EPICS directly.

## Namespace safety

Production name:
```
LEBT:HV_PS:OnStat
```

Simulation name:
```
OTP:LEBT:HV_PS:OnStat
```

The OTP namespace is mandatory for the simulation.

## Layer responsibilities

### Phoebus
- operator visualization
- operator commands
- setpoint entry
- alarms and graphical state representation

### Simulation Soft IOC
- EPICS PV database
- EPICS writes
- simulation readbacks/status
- EPICS-facing namespace

### Simulation Engine
- simulation time
- command consumption
- interlock evaluation
- fault injection
- model execution
- calculated state generation
- PV publication through a backend interface

### Configuration
- initial conditions
- simplified external conditions
- scenario selection
- optional initial commands/setpoints

Configuration must not contain calculated interlock outputs.

## Backend abstraction

```
Simulation Engine
       |
       v
    PVBackend
     /   \
 local   EPICS
 store   adapter
```

The local backend is used for deterministic tests. The EPICS implementation will expose the same contract to a real simulation Soft IOC.

```

    -> EPICS PUT

    -> Simulation Engine
    -> model / logic
    -> EPICS PV update
    -> Phoebus monitor
```
